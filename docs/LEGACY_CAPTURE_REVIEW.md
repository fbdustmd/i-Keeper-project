# 이전 캡처 코드 검토

검토 대상은 [hoho_senpai_homework](https://github.com/fbdustmd/hoho_senpai_homework)의 `Wow.c`와 확장자 없는 `v2` 파일이다. 2026-09-30 읽기만 했으며 이전 저장소는 수정하지 않았다.

## 이미 구현했던 부분

`pcap_open_live`로 실시간 캡처를 열고 `pcap_next_ex`로 패킷을 순회하며 `pcap_close`로 닫는다.
Ethernet·IP·TCP 헤더 위치를 계산해 MAC·IP 주소와 포트, 일부 페이로드를 출력하려는 코드가 있다.
이 열기 → 순회 → 닫기 흐름과 패킷 길이 확인의 필요성을 현재 설계에 활용했다. 코드를 그대로 복사하지 않았다.

## 수정이 필요한 부분

| 대상 | 확인한 문제 | 현재 적용한 원칙 |
|---|---|---|
| Wow.c | caplen을 고정 버퍼 크기와 비교하기 전에 복사 | Phase 1에서는 패킷 복사 자체를 하지 않음 |
| Wow.c | 54바이트 검사만으로 가변 IP/TCP 헤더를 처리 | 이후 파서는 각 오프셋·길이를 읽기 전에 검사 |
| Wow.c | 링크 타입·EtherType·IP 버전·fragment를 확인하지 않음 | 링크 타입을 기록하고 프로토콜 확인은 후속 파서에서 수행 |
| Wow.c | TCP 헤더 위치와 Data Offset 접근의 경계 검사 부족, 길이 뺄셈 underflow 가능 | 검증한 caplen 범위 안에서만 길이를 계산하도록 후속 요구사항 유지 |
| v2 | 10000바이트 버퍼에 caplen을 그대로 복사, 최소 길이 검사 없음 | 신뢰하지 않는 패킷을 고정 크기로 무조건 복사하지 않음 |
| v2 | 일부 TCP 위치 계산에 IHL×5 사용, Ethernet 길이와 TCP Data Offset 위치 누락 | 계층별 검증한 payload_offset을 전달하는 설계 유지 |
| v2 | 이동한 원본 포인터에서 전체 caplen을 1000바이트 배열로 복사 | 원본 범위 초과 읽기·목적지 초과 쓰기 방지 필요 |
| v2 | 출발지·목적지 IP 표기 뒤바뀜, 출력 반복 조건이 실제 남은 길이를 검사하지 않음 | Phase 2 이후 고정 예상값 테스트로 검증 |

이전 코드의 파싱 시도가 있다는 이유로 NetSentry의 Ethernet·IPv4·TCP 단계를 완료 처리하지 않는다.
현재 NetSentry는 캡처 메타데이터만 출력하며 원본 페이로드를 출력하지 않는다.
